# 判定铁律（硬约束——8 字段任一不合格 = 该条未落实）

## 一、八字段判定标准

每条落实报告必须含 8 个字段，缺任一 = 未落实：

| 序号 | 字段 | 合格标准 | 不合格典型 |
|------|------|----------|------------|
| 1 | 条款号 | `[N]` 逐字与手册一致 | 漏方括号、跳号、合并 |
| 2 | 状态 | `✅` 或 `❌` | 空状态、文字代替 |
| 3 | 条款 | 逐字抄录该条正文全文 | 摘要/省略/改写/"见手册第X条" |
| 4 | 代码 | `文件::符号:起止行号` | 只写文件名/无行号/路径不存在 |
| 5 | 落实 | 极尽具体+全量映射，逐句对应条款原文 | 空话/漏点/概述 |
| 6 | 审查 | "问题→修复"或"核对范围+核对项" | 只写"审查通过" |
| 7 | 验证 | 可复跑命令 + 预期断言行 | "已测试"/"跑通了" |
| 8 | 证据 | 真实存在的路径 | "见日志"/路径不存在 |

## 二、治理类条款特殊要求

治理类条款的证据字段必须写 **真实文件路径 + 行号/章节锚点**：
- 合格：`AGENTS.md:12-30`、`.git/hooks/pre-commit:30-38`
- 不合格：只写文件名不写行号、行号与实际不符

## 三、集中单文件禁令

**集中把全部治理内容塞进单个文件 = 违反本条款 = 未落实。**
治理内容必须按治理载体分散布局分散到各自载体（AGENTS.md / rules/ / skills/ / hook / config）。

## 四、五铁律硬化为会话记忆

1. 报告先于实验
2. 未清场不跑实验
3. 落实说明必须含函数名/改动点/断言，不得空话
4. 证据路径必须真实存在
5. 一旦进入论文级区间，两实验不同时各跑论文级

## 五、违反即处置

任一字段不合格 → 该条标注 `❌` → 停工修复 → 重写该条落实报告 → 复验通过后方可继续下一条。
