# 治理载体分散布局

## 一、载体分工总表

| 载体 | 定位 | 本手册治理内容落点 | 示例文件 |
|------|------|-------------------|----------|
| `AGENTS.md`（工作区根） | 长期约束 Agent 行为的项目指令；只放最稳定规则 | 五铁律 + 指向本手册 + 治理载体索引（L1-21） | `AGENTS.md` |
| `rules/` | 固定规则/清单，随事件或 gate 勾选 | 条款归属总则、八字段落实报告格式、判定铁律、阶段执行地图、手册目标、底线清单、状态只认磁盘、防 p-hacking、解冻纪律等 | `rules/*.md` |
| `skills/<name>/SKILL.md` | 可复用工作说明，`$` 触发，正文按需加载 | 逐条落实工序、落实报告书写、verify 核验流程 | `skills/逐条落实工序/SKILL.md` |
| `.git/hooks/pre-commit` | 事件触发自动化 | 0 清场检查、提交前自查、残留审计 | `.git/hooks/pre-commit` |
| `.zcode/config.json` | MCP 外部能力接入 | hooks 配置（session_start、pre_tool_use） | `.zcode/config.json` |
| `archive/` | 清场归档 + 决策日志 | 清场产物、历史权重、decision log | `archive/` |

## 二、硬约束

**① 禁止集中单文件**：治理内容按上表分散落点，禁止把总纲全文 + 八字段格式 + 工序 + 清单全部塞进 `AGENTS.md` 一个文件。
**② `AGENTS.md` 只保留五铁律与载体索引**：细则进 rules / skill / hook。
**③ 证据必须引用文件:行号**：每条治理条款的落实证据 = 该条款实际落点的载体文件:行号。
**④ 最小文件集等效执行**：zcode 等效平台缺省按「最小文件集」条款等效执行（无 skill/插件/MCP 也完整可跑），载体分散是推荐布局、不是运行前提。

## 三、载体创建责任

本条款落实时，治理载体目录与文件必须实际存在于磁盘，不得只列索引而实际缺失。
