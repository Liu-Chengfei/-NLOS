# 八字段落实报告格式规范

## 八字段格式说明

本文件定义八字段格式规范，是八字段格式的权威参考文件。

## 一、字段定义

每条落实报告必须含以下 8 个字段，按顺序书写：

### 字段 1 · 条款号
- 合格：`[40]` 与手册条款编号逐字一致（含方括号）
- 不合格：`41`、`条款41`、`[41条]`、`第41项`

### 字段 2 · 状态
- 合格：`✅`（已落实）或 `❌`（未落实）
- 不合格：空状态、文字"已落实/已完成"

### 字段 3 · 条款（逐字抄录正文全文）
- 合格：全文逐字抄录，含所有分点子项，一字不改
- 不合格：摘要/省略/改写/"见手册第X条"

### 字段 4 · 代码（绝对定位）
- 代码类：`相对仓库根路径::函数名/类名:起止行号`
- 治理类：`载体文件:行号/钩子名`
- 不合格：只写文件名无行号；路径不存在

### 字段 5 · 落实（极尽具体 + 全量映射）
- 条款原文逐句拆 ①②③…，每点写清：该要求 → 落点 → 实现 → 满足
- 必须写到变量名/分支/断言/参数值/返回值/字段级别
- 不合格：空话"已实现"/"按手册执行"；漏点；概述代替全量映射

### 字段 6 · 审查
- 必须写"问题→修复"或"核对范围+核对项"
- 经循环修改的写完整轨迹：违反→改→重映射→不违反
- 不合格：只写"审查通过"/"没问题"

### 字段 7 · 验证
- 可复跑命令 + 具体预期（断言行/输出/数值）
- 不合格：空话"已测试"/"跑通了"

### 字段 8 · 证据
- 真实存在、可直接打开的磁盘路径
- 无独立产物时写明 stdout 落盘位置
- 不合格："见日志"/"已保存"/路径不存在

## 证据字段铁律

证据字段必须满足**可验证三原则**：路径真实存在 + 行号准确 + 可直接打开。

## 二、一句话模板

```
[N] ✅ | 条款: <逐字抄录> | 代码: <文件::符号:行号> | 落实: ①...②... | 审查: 问题→修复 | 验证: 命令→预期 | 证据: 真实路径
```

## 三、提交前自检清单

- [ ] 字段 3 是否逐字抄录了条款全文，含所有分点子项？
- [ ] 字段 4 是否所有路径真实存在，行号是否与文件实际行号吻合？
- [ ] 字段 5 是否条款原文每一句都有对应落实点？
- [ ] 字段 6 是否写全了"问题→修复"或核对范围？
- [ ] 字段 7 的命令能否原样复跑？
- [ ] 字段 8 的所有路径是否真实存在？

任一为否 → 该条作废重做。
