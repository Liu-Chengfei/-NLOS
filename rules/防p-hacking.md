# 条款[15]：解冻纪律与数据纯净性（治理层）

## 核心判据
- 生成器若有任何改动（哪怕一行）→ 解冻 → 修改 → 重新冒烟 → 再冻结 → 清场重做（新改动可能影响数据分布，旧数据作废）
- code freeze后改码必须解冻并记录改动（decision log + git commit），修复后重新冒烟、重新预达标判定、重新冻结，已跑单元按"代码已改必须重跑"作废重跑
- 若改的是数据生成器 → 全量重生成（重生成）+ 重训（重训），论文级数字必须回到RZ链（清场/重生成/重训/验收）后再取

## 禁止项
- 禁止"补跑只挑结果好的单元"（选择性补跑 = 变相p-hacking）
- 禁止"把数据改到结果满意为止"（若属档位/注入语义错误 → 走协议变更流程或缩小声明范围，不得改数据到满意）
- 修复后结果不得与旧结果混用（纪律）
- 任何旧数据集一律不得复用（哪怕旧数据本身合格），论文级结论必须来自这批复现可查的全新数据
- 诊断轨/冒烟数据的任何结果不得以任何形式并入、替代或"补充"验收轨数据（用后即弃或隔离归档，禁止并入任何正式数据）
