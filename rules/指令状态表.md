**断点续跑机制**：
1. 每批 Stage 全部 done + `verify_slim_v5_阶段感知.sh` 通过，才进入下一批（依据：`rules/阶段执行地图.md:5`）
2. 任一 gate 未过不进入下一阶段（依据：`rules/阶段执行地图.md:28`）
3. blocked 状态暂停执行，恢复时从第一个非 done 条款继续
4. 恢复步骤：① 查找状态表中第一个 `❌ blocked` 或 `⏳ pending` 条款 → ② 解决阻塞原因（依赖补齐/数据修复）→ ③ 将该条款状态改为 `✅ done` → ④ 从该条款重新执行后续批次
5. 前置依赖检查：`.git/hooks/pre-commit:111`（check_dependencies 函数定义）、`.git/hooks/pre-commit:229`（调用点），检查 [2]-[6] 依赖链，未满足则 blocked 并退出
