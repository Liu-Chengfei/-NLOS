# 状态只认磁盘、不认记忆

## 铁律（硬约束）

**状态只认磁盘；不认记忆。** 任何"进度/结果/是否已做"的判断一律以磁盘上的产物为准：

**状态只认磁盘，不凭记忆。** 每批开工必须核验磁盘锚点，不得凭会话记忆推进。
- manifest 文件（路径、内容、时间戳）
- decision log（决策记录）
- 产物文件（仿真数据集、权重、报告、日志）
- git commit 记录

执行者"我记得跑过" = 零证据 = 未落实。

## 跨批交接纪律

跨批交接一律写 decision log，内容包括：
1. 本批完成的操作（清场、生成、训练、评估）
2. 本批产物的路径与摘要
3. 下批需接续的状态
4. 已知问题或待处理事项

## 磁盘锚点校验清单

每次开工前必须核验以下磁盘锚点（任一缺失 = 停工，不得凭记忆推进）：
- [ ] `清场验证.txt` 存在且最近时间戳吻合
- [ ] `manifests/` 目录存在且非空（或已清场记录为 0 项）
- [ ] `decision_log.json` 或 `decision_log_<stage>.md` 存在
- [ ] `outputs/compliance_report_*.md` 存在（对应已落实条款）
- [ ] `.git/HEAD` 指向有效 commit（git 状态干净）

## 违反处置

发现"凭记忆判断状态"的行为 → 立即停止 → 重新磁盘核验 → 补 decision log → 方可继续。
