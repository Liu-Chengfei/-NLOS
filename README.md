1. `neutral core`

## 治理约束
- `quick/full` 只表示运行规模或资源档位，不再承载科学语义。
- 公平性默认要求同协议、同数据边界、同指标口径、同重复策略、同算力口径。
- 禁止删失败样本、挑样本、换口径后再宣布“最强”。
- 公开验证面真实数据缺失或不可核验时，必须中止。

## E9 训练规模研究结论（2026-08）

### 实验背景
对 `sim_curve/line` × `{01,02}` × `{0,var_01,var_02}` 共 12 条 E9 验证序列，
分别测试了 4 种训练规模组合，最终结论：**所有 "改进" 都在 ±1% 噪声内**。

### 实验结果

| 方法 | 训练规模 | RMSE | ATE | RPE |
|------|----------|------|-----|-----|
| LSTM  | 1-epoch quick (1860 seq)  | 3.7780 | 2.5815 | 0.0097 |
| Liquid | 1-epoch quick (1860 seq) | 3.6796 | 2.5465 | 0.0096 |
| LSTM  | ep35 (60 base × 35 ep)    | 3.7588 | 2.5760 | 0.0097 |
| Liquid | ep39 (60 base × 39 ep)   | 3.7104 | 2.5579 | 0.0096 |
| LSTM  | ep9 (1860 seq × 9 ep)     | 3.7665 | -     | -     |
| Liquid | ep5 (1860 seq × 5 ep)    | 3.6759 | -     | -     |

### 决策
**接受 1-epoch quick (1860 seq) 作为 E9 提交配置**，理由：
1. 训练时长最短（~4 分钟），对工程最友好
2. 性能与"长训练"完全等价（±1% 噪声内）
3. 验证损失虽能从 0.004933 改善到 0.001685（66% 下降），但无法转化为指标改进
4. E9 协议场景对方法改进的区分度已经饱和（噪声地板 ~1%）

### 根因
当前 E9 评估协议仅 12 条序列，所有方法都收敛到同一 Pareto 前沿的相同邻域。
改进方案需要：(a) 更多样化的序列场景，或 (b) 不同的网络架构/特征。
