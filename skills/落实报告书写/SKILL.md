# 落实报告书写（八字段格式应用）

## 一、模板

```
[N] ✅ | 条款: <逐字抄录全文> | 代码: <文件::符号:行号> | 落实: ①...②... | 审查: 问题→修复 | 验证: 命令→预期 | 证据: 真实路径
```

## 二、逐字段书写规则

### 字段 1 · 条款号
`[N]` 与手册条款编号逐字一致。

### 字段 2 · 状态
`✅` 或 `❌`，不允许空/文字。

### 字段 3 · 条款（逐字抄录）
- 全文逐字抄录，含所有分点子项
- 禁止摘要/省略/改写/"见手册第X条"
- 条款原文较长时分段抄录，每段保留原文标点

### 字段 4 · 代码（绝对定位）
- 代码类：`相对仓库根路径::函数名/类名:起止行号`
- 治理类：`载体文件:行号/钩子名`
- 所有路径必须在执行前逐行核验存在

### 字段 5 · 落实（全量映射）
条款原文拆 ①②③…，每点写：该要求 → 落点 → 实现 → 满足
写到变量名/分支/断言/参数值/返回值/字段级别。
禁止：空话/漏点/概述代替全量映射。

### 字段 6 · 审查
必须写"问题→修复"或"核对范围+核对项"。
经循环修改的写完整轨迹：违反→改→重映射→不违反。

### 字段 7 · 验证
可复跑命令 + 具体预期断言行。
禁止："已测试"/"跑通了"。

### 字段 8 · 证据
真实存在、可直接打开的磁盘路径。
无独立产物时写明 stdout 落盘位置。
禁止："见日志"/路径不存在。

## 三、治理层条款特殊要求

治理层条款（第 0 阶段）的证据字段必须引用治理载体文件:行号：
- `AGENTS.md:3-8`（五铁律）
- `rules/判定铁律.md:1-39`（八字段判定标准）
- `.git/hooks/pre-commit:8-19`（0 清场）

## 四、自检清单

提交前逐项核对：
- [ ] 字段 3 是否逐字抄录了条款全文？
- [ ] 字段 4 所有路径是否真实存在、行号是否吻合？
- [ ] 字段 5 是否条款原文每一句都有对应落点？
- [ ] 字段 6 是否写全了"问题→修复"？
- [ ] 字段 7 的命令能否原样复跑？
- [ ] 字段 8 的所有路径是否真实存在？

任一为否 → 作废重做。
