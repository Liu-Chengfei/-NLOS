# 逐条落实工序（四步闭环）

## 第一步：查

1. 读该条款完整原文（八字段中的「条款」字段必须逐字抄录）
2. 查磁盘现状：对照条款要求的落点，逐文件验证是否存在
3. 禁止凭记忆判断状态

## 第二步：落

把条款翻译成代码/配置/脚本落点：
- **代码类**：文件路径 + 函数/类/配置键 + 行号（如 `model/heads.py::RiskHead.forward():88-95`）
- **治理类**：载体文件 + 行号/钩子名（如 `rules/状态只认磁盘.md:1-27`）

每点按四段写清：该要求 → 落点 → 实现 → 满足

## 第三步：验

1. 打开落点代码逐行核对
2. 条款原文的每一句/每一个数值/每一项禁止都对应落实点
3. 任一未落实 = 当场改，改完回查直到审查通过
4. 运行验证命令，确保输出与预期吻合

## 第四步：报

按八字段格式写该条落实记录，写完自查：
- [ ] 条款号是否 `[N]` 格式，与手册一致？
- [ ] 状态是否 `✅` 或 `❌`？
- [ ] 条款字段是否逐字抄录全文？
- [ ] 代码字段路径是否真实存在、行号是否吻合？
- [ ] 落实字段是否逐句对应条款原文、无漏点？
- [ ] 审查字段是否写全了"问题→修复"或核对范围？
- [ ] 验证命令是否可复跑？
- [ ] 证据路径是否真实存在？

任一为否 → 作废重做。
