## 0 · 执行总纲（先读这个，其余全是细则）

### 两阶段制（最高优先级，本手册第一条）
- **第 1 阶段 · 落实报告期（禁跑实验）**：8 个 Stage（1 定义→8 提交）只是条款分组与落实顺序，不是第一阶段要执行实验。本阶段只做代码落实：0 清场 → 按 Stage 1→8 逐条把代码映射/审查/改到完美 → 每条写落实报告。**禁止跑任何实验**（冒烟/quick/预达标/全量/重跑全部禁止）。
- **第 2 阶段 · 实验期**：Stage 1→8 全部落实报告写完 + `bash verify_slim.sh 本手册` 核验 PASS → 才开始执行 Stage 3 生成数据→4 预检→5 训练→6 验收→7 诊断→8 提交对应的实验（Stage 1/2 是配置与代码落实，无独立实验动作）→ 每个实验开跑前再清场 → 按 Stage 顺序跑。

### 0 清场（第一阶段第一动作，硬约束）
- 写 `clear_workspace.py`：清空仿真数据集（npz/manifest）+ 权重（checkpoint）→ archive/，跑它，输出写入落实报告。
- 第二阶段每个实验开跑前再跑一次并贴输出；未清场 = 禁止生成新数据/初始化训练/加载旧权重。
