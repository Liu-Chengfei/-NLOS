# 线程编排操作单 · Zcode 本地执行（v50 配套）

> 用途：在 zcode 平台把手册 ⑱-3 的"主控/比对/审计/扩展多线程"从**单会话自我模拟**变成**真实独立会话**。
> 原则：**软约束靠文字，硬约束靠机制。子线程 = 真实独立会话，不是 AI 自己说"我复核过了"。
> **语言铁律：主控/审计两个会话的一切汇报、日志、审计发现、拦截报告、给用户的进度更新一律简体中文**（代码/命令/路径/机器输出原文不译）。发现英文输出 = 立即提醒改正。
> 机器裁判：`check_progress.py`（工作区根目录）是勾选进度的唯一机器裁判——主控每勾一条必须跑它且 CHECK-PASS，审计每抽查一批也跑它复核，一切以机器输出为准，不认口头自述。**

## 一、每个实验开 2 个会话（最小真实线程集）

| 会话 | 角色（手册⑱-3⑨） | 发什么 | 写权限 |
|---|---|---|---|
| 会话 A | 主控线程（主执行通道） | 提示词 v50 + 执行手册 + 命令集 + /goal | ✅ 唯一写权限 |
| 会话 B | 审计线程（独立审计通道） | 提示词 v50（节选）+ 审计任务书 | ❌ 只读 |

## 二、会话 A（主控）开场四件套
1. 粘贴 实验执行者提示词 v50（含 3.6 节）
2. 附上/指向 执行手册（正文 = 手册真源）
3. 附上/指向 命令集-101 条（异步）/ 96 条（消融）
4. 发送 /goal 主线程指令（见第四节模板）

## 三、会话 B（审计）开场三件套
1. 粘贴 提示词 v50 的 3.6 节 + 第 8/9 节
2. 指向同一工作区（同一份 checklist_progress.md、decision log、manifest）
3. 发送审计任务书（见下）

```
/goal 你是本实验的独立审计线程（手册⑱-3⑨(c)，只读不写）。
职责：每隔一段时间读取工作区 checklist_progress.md 与 decision log，
对主控线程已勾选的条目做独立抽查——①条号是否连续、有无跳号；
②每条证据路径是否真实存在（ls 验证）；③结论与证据是否一致、有无"勾了没执行/执行了没勾"；
④当前批次的 DAG 阶段是否正确（有无提前消费下游产物）。
机器复核：每次抽查跑 `python3 check_progress.py --next checklist_progress.md 命令集.md` 核对"机器说的下一步"
与主控声称在做的是否一致（不一致 = 主控走偏/遗忘，立即报告）；用 `--status` 核对"主控记忆的进度 vs 磁盘真源"。
发现任何偏差：写入 decision log 的"审计线程发现"区（只写不改任何实验文件），并向用户报告。
你的存在 = 主控线程不能自己审自己。
```

## 四、/goal 主线程指令模板（v50 强化版）

见对话交付正文（四段式：执行方式=逐条核对 / 进度文件 / 条号连续 / DAG gate 全绿前禁碰代码）。

## 五、防跳指令/防不勾/防假装的机制闭环

| 事故 | 机制 | 谁发现 |
|---|---|---|
| 跳指令 | 条号连续性强制（当前条号必须=最后一条+1，跳号即停） | 主控自查 + 审计抽查 |
| 执行了不勾 | 只有写入 checklist_progress.md 才算勾选 | 审计对照证据路径 |
| 勾了没执行 | 每条必须附真实存在的证据路径，ls 可验 | 审计 ls 验证 |
| 没认真执行 | 独立审计会话 B 抽查 + 每 5 条独立复核视角 + check_progress.py 机器校验 | 审计线程 + 机器 |
| 伪造证据/假装核过 | check_progress.py [R3] 证据路径必须真实存在，伪路径直接 CHECK-FAIL | 机器（不可绕过） |
| 无子线程 | 会话 B = 真实独立会话（只读），不是自我模拟 | 用户开 2 个会话 |

## 六、两个实验 = 4 个会话（推荐）
异步工作区：会话 A1(主控) + 会话 B1(审计)；消融工作区：会话 A2(主控) + 会话 B2(审计)。
两工作区互不读写（手册⑨/⑪），论文级（RZ 系列）永不同时运行（⑨ 硬互斥）。

## 七、审计节奏
主控每完成 5 条勾选 / 每个 DAG 阶段切换时，提示"审计线程请抽查"；会话 B 至少每个 DAG 阶段结束查一次。
审计发现偏差 → 写 decision log"审计线程发现"区 → 主控停下修正 → 复核通过再继续。
审计线程每次抽查后自己跑一遍 `python3 check_progress.py`，把 CHECK-PASS/CHECK-FAIL 输出贴进 decision log——机器复核与人工抽查双轨，互不替代。
