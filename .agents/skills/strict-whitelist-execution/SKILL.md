# strict-whitelist-execution

## 1. 使用场景
- 用户边界严格、目录多、容易顺手扩任务时。

## 2. 不适用场景
- 不用于重新定义科学真相。

## 3. 输入要求
- 已授权目录/文件、未授权范围、目标交付、最小验证。

## 4. 输出格式
- `允许范围 / 明确不做 / 已改文件 / 未改高风险区 / 验证`。

## 5. 决策顺序
1. 先内部重述白名单。
2. 只做最小改动。
3. 只做与改动直接对应的验证。

## 6. 禁止事项
- opportunistic refactor、顺手修、隐式扩范围。

## 7. 与其他 skill 的边界
- 这是执行约束，不替代 domain 审查方法。

## 8. 最小验证/复核要求
- closeout 必须显式写未改高风险项。
