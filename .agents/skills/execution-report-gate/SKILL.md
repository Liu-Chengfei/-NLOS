## §1 · 落实报告格式（逐字抄录手册第 17–119 行）

> 以下为手册原文逐字块，未做任何改写。写报告前完整阅读本节。

### 落实报告格式（一行一条，机器可核验，缺任一字段或字段不合格 = 未落实）
**八字段逐字段规范（新增「条款:」字段——逐字抄录该条正文全文，防摘要/防改写的最强约束）——每个字段都按"合格标准 / 不合格典型 / 合格示例"三级写清，缺项、含糊、空话 = 该条未落实：**

**字段 1 · 条款号**
合格标准：`[46]` ——与手册条款编号逐字一致（含方括号）；一批报告按编号从小到大连续书写，不跳号、不重复、不倒序、不合并多条为一行。
不合格典型：`41`（漏方括号）、`条款41`、`[41条]`、`第41项`、`[41.1]`；漏号/跳号/一条覆盖多条款。
合格示例：`[46] ✅ | ...`（方括号 + 纯数字，与手册一字不差）。

**字段 2 · 状态**
合格标准：每行状态只能是 `✅`（已按迭代闭环落实到位——含"本就满足、审查确认"与"发现违反、当场修好"两种）或 `❌`（未落实）；不允许有无状态行；写 `❌` 的行必须停下处理，不得带病进下一条。
不合格典型：空状态；用文字"已落实/已完成"代替符号；`❌` 却继续前进。
合格示例：`[46] ✅ | ...`（落实完成后状态必须是 ✅ 才进下一条）。

**字段 3 · 条款（逐字抄录该条正文全文，落实的唯一对照基准）**
合格标准：**逐字抄录该条正文全文，含所有分点子项，不得摘要、不得省略、不得改写、不得"见手册第X条"代替**——复核者拿报告上的「条款:」字段与手册原文逐字比对，一字不差才算过；正文里有几条分点/几个子项就抄几条/几项，**漏任何一个子项 = 未落实**。
不合格典型：写"见手册第 45 条"；只抄标题不抄正文；摘要式转述（"本条要求定义 7 变体"）；漏抄分点子项；改写措辞。
合格示例：`条款: **[11]** **7 变体定义** ——**Full**（完整模型，4 头全开：...）...`（正文逐字全文，一字不差）。

**字段 4 · 代码（绝对定位，防"文件对了符号找不到"）**
合格标准（代码类）：`相对仓库根路径::函数名/类名:起止行号` ——函数/类/方法/配置键写到符号**并附起止行号**，如 `model/heads.py::RiskHead.forward():88-95`、`config.py::BATCH_SIZE:45`、`data_gen.py::inject_nlos():120-145`、`stats.py::wilcoxon_paired():300-320`；多个落点用 `;` 分隔；落点必须真实存在、复核者可打开并跳转到精确行。
合格标准（治理类）：`文件 + 章节/行号/钩子名`，如 `AGENTS.md` 五铁律、`.git/hooks/pre-commit` 第 12–30 行、`checklist_gate.md` [6] 项。
不合格典型：只写文件名不写符号（`config.py` 不合格，须到 `config.py::BATCH_SIZE:45`）；写了符号没写行号；写"相关代码/见代码/主程序"；落点路径不存在。
合格示例：`代码: variants.py::VARIANT_SPECS:10-25; config.py::VARIANT_KEYS:30-32`

**字段 5 · 落实（核心字段，写透"改了什么、在哪、怎么生效"；极尽具体 = 变量名/分支/断言/参数值/返回值/字段全写出；逐句覆盖条款原文全部内容 + 逐点映射，必须覆盖条款全部内容）**
合格标准（极尽具体 + 全量映射，硬约束）：**第一步先读该条款完整原文（即字段 3 抄录的全文）；第二步落实字段必须逐句覆盖条款原文的全部内容——条款原文的每一句陈述、每一个数值、每一项禁止、每一个判据、每一个出口，都必须有对应的落实点（只能改写表述、不得省略任何一句内容）；第三步再把条款的每条独立要求拆成 ① ② ③ …（几条要求就拆几点，少一点 = 未落实）；每一点按"该要求 → 落点 → 实现 → 满足"四段写清**——落点（代码类写 `文件::符号:行号` + 关键变量/参数/断言；治理类写 `文件 + 章节/行号` + 触发时机 + 执行逻辑）、实现（改了什么/用哪个函数哪个类哪个配置键/什么变量名/什么判断分支/什么 assert/取什么参数值/返回什么/写什么字段）、满足（该要求如何达成，能让人不看代码就核对）。**"极尽具体"= 落实字段必须写到变量名、分支、断言、参数值、返回值、字段级别——写"已实现"是空话，写"config.py::BATCH_SIZE=16, 训练循环 batch_size 从该常量读入, 冒烟日志断言 shape[1]==16"才算落实。** 条款 3 条要求就写 3 点，条款原文 5 句就至少 5 个对应点；不允许合并成 1–2 句概述、不允许漏点、不允许写"和上面一样"；条款原文被省略的任何一句/数值/禁止项 = 未覆盖 = 未落实。
不合格典型：只写"已落实/已实现/按手册执行/完成"；整句照抄条款原文不改写（落实字段要写"怎么落的"，不是复读条款）；写"和上面一样/同上"；没有落点、没有变量名/分支/断言/参数值；**条款含多条要求却只写 1–2 句概述（漏点 = 未落实）**；**条款原文中的任何一句/数值/禁止项未在落实字段出现（漏内容 = 未落实）**。
合格示例：见下方"完整示例"（代码类 [46] 的落实字段为合格范本：条款原文每一句要求都有对应点，每点含变量名/分支/断言/参数值/返回值，①②③…逐点对应条款要求）。
边界：本字段按**极尽具体 + 全量映射制**判定——落实字段必须与条款原文**逐句对应**：条款原文有多少句要求，落实字段就有多少个对应点，不允许漏句、漏数值、漏禁止项；每点必须写到**变量名/判断分支/assert/参数值/返回值/字段**级别（写不出具体符号 = 没真落实）；不设固定"6 要素/3 要素"模板，但**全量映射比模板更严：每点必须能对应条款原文的一句话/一个要求，不能漏、不能并、不能概述**。

**字段 6 · 审查（独立核对 + 问题→修复闭环 + 循环修改轨迹，逐行核对）**
合格标准：必须写"问题 → 修复"两部分：`问题: <逐行核对发现的具体问题：哪行/哪个值/缺哪个断言/与手册哪句不符> → 修复: <当场怎么改：改动前→改动后要点，或新增了什么函数/断言/配置项；含文件:行号>`；**本条若经循环修改（一次没改对、改了又查、查了又改），必须写明完整轨迹：`违反（哪行/哪个值/哪句不符）→ 改（改动前→改动后要点）→ 重映射（重新核对落点与条款）→ 不违反（重审确认通过）`，一轮一轮写清，禁止只写最后一句"修复:已改好"**；审查确实未发现问题时写"逐行核对未发现问题（核对范围: <文件> 第 N–M 行，核对项: <条款要点逐项>）"。
不合格典型：只写"审查通过/没问题/已核对"；既没有问题也没有核对范围；写"和落实字段一样"；**经多轮修改却只写"修复:已改好"、无「违反→改→重映射→不违反」轨迹**。
合格示例：`审查: 问题: 初版 LNN 仍保留 risk 头可训练参数（model/heads.py:90，违反"真移除"）→ 修复: 摘除 risk 头分支并 requires_grad=False（改动前: requires_grad=True → 改动后: False + 头分支从计算图摘除，model/heads.py:88-95）`

**字段 7 · 验证（真实可执行命令 + 预期输出/关键断言行，须能复现本条落实）**
合格标准：`命令: <可复跑命令> → 预期: <输出/断言/数值/关键断言行>`；命令必须能原样复跑并**实际复现本条落实**（如 `python -m pytest tests/test_variants.py`、`bash -n .git/hooks/pre-commit`、`python -c "..."`、`grep ...`）；预期写清"看到什么算过"（如 `7 passed`、`exit 1 并打印命中清单`、`无 NaN/Inf`、`assert set(VARIANT_SPECS)==set(VARIANT_KEYS) 通过`）。
不合格典型：只写"已测试/跑通了/验证过了"；命令不可复跑（写"跑一下看看"）；预期是空话（"正常/通过"）；命令与落实内容无关（验了 A 却说落实了 B）。
合格示例：`验证: 命令: python -m pytest tests/test_variants.py → 预期: 7 passed，断言 VARIANT_SPECS 恰 7 项、wo_liquid 无训练路径`

**字段 8 · 证据（磁盘真实存在的产物/日志/测试输出路径；无产物则写明本次命令 stdout 落盘位置）**
合格标准：真实存在、复核者可直接打开的相对路径（如 `logs/smoke_20260914_seed1_full.log`、`manifests/seed01/manifest.json`、`tests/test_variants.py`、`decision_log_run1.md`）；**无独立产物时写明本次验证命令 stdout 的落盘位置**（如 `验证输出已重定向至 logs/verify_variants_20260914.log`）；治理类证据含决策日志/钩子文件/清单。
不合格典型：写"见日志/已保存/略"；路径不存在；路径指向 archive/备份副本（正式证据必须来自当前生效版本）；不写 stdout 落盘位置。
合格示例：`证据: tests/test_variants.py; logs/smoke_variants_20260914.log; 验证输出: logs/verify_variants_20260914.log`

**一句话模板（合格行长什么样）**
```
[编号] ✅ | 条款: <逐字抄录该条正文全文，含所有分点子项，不得摘要/省略/改写> | 代码: 文件::函数/类:起止行号（多落点用 ; 分隔） | 落实: ①<条款原文第 1 句/第 1 项要求 → 落点 → 实现（变量名/分支/断言/参数值/返回值）→ 满足>; ②<条款原文第 2 句/第 2 项要求 → …>; …（极尽具体 + 全量映射：条款原文每一句/每一数值/每一项禁止都必须有对应点，一条不漏） | 审查: 问题: <哪行/哪个值/缺哪个断言/与手册哪句不符> → 修复: <改动前→改动后要点，文件:行号>（经循环修改的写全 违反→改→重映射→不违反 轨迹，一轮一轮写清） | 验证: 命令: … → 预期: <输出/关键断言行> | 证据: 真实路径; 验证输出: <stdout 落盘路径>
```
治理类同构：`代码: 文件+章节/行号 | 落实: ①<条款原文第 1 句要求→触发时机→执行逻辑→满足>; ②<条款原文第 2 句要求→…>; …（极尽具体 + 全量映射：条款原文每一句/数值/禁止项都有对应点，一条不漏） | 审查: 问题→修复 | 验证: 命令→预期 | 证据: 真实路径; 验证输出: stdout 落盘路径`

**批量提交前自检（每批报告写完、交出去前逐条过一遍）**
0. "条款"字段是否逐字抄录了该条正文全文、含所有分点子项、一字未改？——摘要/省略/改写 = 未落实。
1. 有人不看代码，仅凭"落实"字段能否核对这次改动？——不能 = 未落实；落实里有没有变量名/分支/断言/参数值/返回值？——没有 = 未落实。
2. "审查"字段是否有"问题→修复"（含哪行/哪个值/改动前后）或"核对范围+核对项"？——只有"审查通过" = 未落实；本条若经循环修改，是否写全"违反→改→重映射→不违反"轨迹（一轮一轮写清，禁止只写最后一句）？——没写轨迹 = 未落实。
3. "验证"命令能否原样复跑、预期是否具体到断言行？——"已测试" = 未落实。
4. "证据"路径能否点开？无产物时是否写明 stdout 落盘位置？——"见日志" = 未落实。
5. 条款号是否从小到大连续、无跳号无合并？——违反报告顺序铁律 = 本批作废。
任一为否 → 该条/本批重写，禁止带着含糊字段提交。

> **判定铁律**：8 字段任一缺失、含糊或空话（如"已落实/已实现/按手册执行/审查通过/已测试/见日志"）= 该条未落实；**"条款"字段未逐字抄录该条正文全文（摘要/省略/改写/写"见手册第X条"）= 该条未落实**；**"代码"字段无起止行号（绝对定位缺失）= 该条未落实**；**"落实"字段未写到变量名/分支/断言/参数值/返回值/字段级别（写不出具体符号 = 没真落实）= 该条未落实**；"审查"无"问题→修复"（含哪行/哪个值/改动前后）或"核对范围" = 未落实；**经循环修改的条款"审查"无「违反→改→重映射→不违反」完整轨迹（一轮一轮写清） = 未落实**；"证据"路径不存在且未写明 stdout 落盘 = 未落实。**落实字段按极尽具体 + 全量映射制判定：条款原文每一句/每一数值/每一项禁止都必须有对应落实点；条款含 N 条独立要求，落实字段必须写满 N 点（每点 = 该要求→落点→实现→满足，落到变量名/分支/断言/参数值）；少一点、并一点、漏一点、漏条款原文任何一句内容、用 2–4 句概述代替全量映射 = 该条未落实。**

### "落实:"字段要素说明（极尽具体 + 全量映射制，不设二级清单）
"落实:"字段为**极尽具体 + 全量映射制（硬约束）**：先读条款原文（即字段 3 逐字抄录的全文），把条款原文的**每一句陈述/每一个数值/每一项禁止**都拆成 ①②③…（条款原文有多少句要求就拆多少点，漏任何一句 = 未落实），每点写清"该要求 → 落点（代码类写 `文件::符号:行号` + 关键变量/参数/断言；治理类写 `文件 + 章节/行号` + 触发时机 + 执行逻辑）→ 实现 → 满足"；**"极尽具体"= 每点必须写到具体符号级：哪个函数/哪个类/哪个配置键、什么变量名、什么判断分支、什么 assert、取什么参数值、返回什么、写什么字段**——写不出具体符号 = 没真落实 = 未落实；**条款几条要求写几点，少一点 = 未落实**。不再要求"代码类 6 要素 / 治理类 3 要素"的二级清单——但极尽具体 + 全量映射比清单更严：**每点必须能对应到条款原文的一句话/一个要求，条款原文的每一句内容都必须有对应点，不能漏、不能并、不能概述**。

### 逐条落实工序（迭代闭环，硬约束，每条条款的唯一执行方式）

**每条条款的落实不是"看完就写报告"，而是下面这个迭代闭环。逐条执行，禁止跳过任何一步：**

```
1. 看条款   → 读该条款完整原文（禁止凭印象、禁止只看摘要）
2. 映射代码 → 把条款翻译成对应代码/脚本/配置/命令的落点（文件路径 + 函数/类/配置键）
3. 审查     → 打开落点代码，逐行核对是否完美严格落实该条款（不落实 / 不完美 = 违反）
        │
        ├── 违反 → 4. 改代码：当场直接改，不留 TODO、不留"注释掉的旧实现"
        │           └→ 改完回到 2.，重新映射、重新审查（看条款→映射→审查→改，循环）
        │              直到"审查通过（不违反）"才允许进入下一步
        │
        └── 不违反 → 直接进入下一步
5. 写报告   → 按「落实报告格式」写该条款的落实记录（**先逐字抄录该条正文全文到"条款:"字段（含所有分点子项，不得摘要/省略/改写）**；"落实:"字段按极尽具体 + 全量映射制：先读条款原文，逐句覆盖条款原文全部内容——每一句/每一数值/每一项禁止都有对应点，每点落到变量名/分支/断言/参数值/返回值/字段级，条款每条要求→落点→实现→满足逐点写清，一条不漏、一句不漏）
6. 下一条款 → 回到 1.
```

**要点（违反 = 该条款未落实）：**
**"改代码"不是终点，"改完重新看条款、重新映射、重新审查直到改好"才是** ——一次改不到位就再改，循环直到审查通过；
**禁止"改了代码但没回看条款就写报告"**（改偏了也算未落实）；
**禁止"觉得没问题就直接写报告"**（必须真的打开代码逐行核对过）；
**禁止"写报告时才发现没改"**（先改好、再写报告，报告里的内容必须与落盘代码一致）；
每条条款落实完成后，落实记录即成为该条款"已落实"的证据；**未写落实记录的条款一律视为未落实**（对应 Stage 7 落实报告门禁条款）。

### §2.5 常见错误与处理

| 错误类型 | 典型表现 | 正确处理 |

| 漏写行号 | `config.py` | `config.py::BATCH_SIZE:45` |

| 无轨迹审查 | "修复:已改好" | 写全「违反→改→重映射→不违反」一轮一轮 |

| 跳号/合并 | 一条写多条条款 | 按编号连续书写，一条一行 |

## §3 · 核查要点（每次写报告前自检）

0. **条款字段**：是否逐字抄录了该条正文全文、含所有分点子项、一字未改？
1. **落实字段**：是否有人不看代码也能核对？是否写到变量名/分支/断言/参数值/返回值/字段级？
2. **审查字段**：是否有"问题→修复"（含哪行/哪个值/改动前后）或"核对范围+核对项"？经循环修改的是否写全轨迹？
3. **验证字段**：命令能否原样复跑？预期是否具体到断言行？
4. **证据字段**：路径能否点开？无产物时是否写明 stdout 落盘位置？
5. **顺序**：条款号是否从小到大连续、无跳号无合并？

任一为否 → 该条/本批重写，禁止带着含糊字段提交。
