# external-evidence-harvester

## 1. 使用场景
- 用户要求看网帖、扩大资料范围、补审查方法时。
- `Context7` 无法覆盖目标资料，或需要框架文档之外的外部证据时。
- 已经用 `cocoindex-code` 做过一轮语义召回，但还需要关键词矩阵补扫时。

## 2. 不适用场景
- 不用于拿社区帖子直接改写仓内协议。
- 不替代高风险逐行精查。

## 3. 输入要求
- 主题、优先级层级、当前仓内待查问题。
- 关键词族、目标目录、排除目录。

## 4. 输出格式
- `来源 / 类型 / 可吸收检查法 / 是否需要官方复核`。
- 若做仓内补扫，可输出：`关键词族 -> 命中文件 -> 命中行 -> 风险标签`。

## 5. 决策顺序
1. 先判是否属于 `Context7` 可直接覆盖的官方文档。
2. 再判是否应先用 `cocoindex-code` 做语义检索。
3. 若语义检索后仍需补扫，再按主题分关键词族，跑源码、配置、脚本、测试四层。
4. 再看官方。
5. 再看主流社区。
6. 最后看垂直社区和冷门平台。

## 6. 禁止事项
- 用单一社区帖子下硬结论。
- 只搜单个关键词就宣布覆盖充分。

## 7. 与其他 skill 的边界
- 官方库文档优先交给 `Context7`。
- 默认代码检索入口交给 `cocoindex-code`。
- 本 skill 同时覆盖仓外证据采集和仓内关键词矩阵补扫；具体落地仍由对应 auditor 执行。

## 8. 最小验证/复核要求
- 每条外部结论至少要能回仓内事实或官方源确认。
- 每个关键词族都要覆盖源码、配置、脚本、测试至少一个面。
