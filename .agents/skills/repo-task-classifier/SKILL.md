# repo-task-classifier

## 1. 使用场景
- 进入新任务、新问题类或新微批次前。
- 审查治理冲突、协议归属、根/局部覆盖顺序时。

## 2. 不适用场景
- 不替代实际修复或测试。

## 3. 输入要求
- 用户目标、涉及目录、可动/不可动边界。
- 相关文件列表、冲突点、当前解释路径。

## 4. 输出格式
- `任务层级 / 风险级别 / 权威源 / 最近 AGENTS / 需要 skill / 最小验证`。
- 若涉及治理冲突，补充：`谁是主定义 / 谁只能引用 / 冲突点 / 收紧方案`。

## 5. 决策顺序
1. 先判任务层级。
2. 再判风险。
3. 再判是否应先用外部能力取上下文。
4. 再分科学真相层和施工层、根与局部。
5. 再列权威源与边界。
6. 最后定最小验证。

## 6. 禁止事项
- 先改后判、先跑全仓再缩范围。
- 用低权威文件覆盖高权威文件。

## 7. 与其他 skill 的边界
- 库/API/框架文档优先走 `Context7`。
- 大仓语义检索、跨文件代码召回优先走 `cocoindex-code`。
- scope 漂移风险高时必须配 `strict-whitelist-execution`。
- 本 skill 同时覆盖任务归类和权威/冲突判定，但不负责写文件本身。

## 8. 最小验证/复核要求
- 分类结果必须能解释为什么要读这些文件、为什么不读那些。
- 至少核对一遍引用链和一遍最近目录覆盖链。
